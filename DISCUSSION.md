### Why it is the DACL and not the console

* `setTokenDefaultDaclGrant()` merges one full-access ACE for `tempWriteSidPtr ?? writeSidPtr ?? worldSid` into the restricted token's Default DACL (`sandbox-windows-acl/lib/types-*.js`).
* `worldSid` is `makeWellKnownSid(api, 1)` — `read-only` falls back to it, `workspace-write` uses the capability SID instead.
* The package README states `Everyone` "is required for early DLL initialization and CNG".
* On this host the process token's Default DACL was `{BUILTIN\Administrators, NT AUTHORITY\SYSTEM, <logon SID>}` — no `Everyone`. `read-only` therefore lands an `Everyone` ACE where `workspace-write` does not.

The console-less host is what makes the child exercise that path at all: it must create a console of its own during DLL initialization, and that creation is what fails. Give the runner a console and the child never needs to; add `Everyone` to the Default DACL and the creation succeeds.

### Remedies

* Structural: add `Everyone` to the grant in `setTokenDefaultDaclGrant()` for `workspace-write` as `read-only` already does (byte/line-level source patch previously attached in #8775 / #9038).
* Workaround without patching the app: give the runner process a console — `[execPath, --import <console-shim>, runner.js, …]` — implemented as a `dsh-plugin` bundle: #9282.
